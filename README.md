# Northern Hills Aerial Services

Company website for Northern Hills Aerial Services, built on **Drupal 11**
(standard install profile) with **DDEV** for local development on
**OrbStack** (or any Docker provider).

| Component | Version |
| --- | --- |
| Drupal core | 11.4.9 (`drupal/core-recommended` ^11.4) |
| Drush | 13.8 |
| PHP | 8.5 |
| Database | MariaDB 10.11 |
| Web server | nginx-fpm |
| Node.js | 22 |

## Prerequisites (macOS)

1. [OrbStack](https://orbstack.dev/) — install it and start it once.
2. DDEV (v1.24.10 or newer, for PHP 8.5) and mkcert:
   ```sh
   brew install ddev/ddev/ddev
   mkcert -install
   ```

DDEV detects OrbStack automatically; no extra configuration is needed.

## First-time setup

```sh
git clone git@github.com:westerfer/northern_hills_aerial_services.git
cd northern_hills_aerial_services
ddev start
ddev site-install
```

`ddev site-install` runs `composer install`, installs Drupal from the
configuration committed in `config/sync`, and prints a one-time admin login
link. The site is at **https://northern-hills-aerial-services.ddev.site**.

To get another login link later: `ddev drush uli`.

## Everyday commands

| Task | Command |
| --- | --- |
| Start / stop | `ddev start` / `ddev stop` |
| Open the site | `ddev launch` |
| Clear caches | `ddev drush cr` |
| Export config after changes in the UI | `ddev drush cex` |
| Import config after pulling | `ddev drush cim` |
| Add a module | `ddev composer require drupal/<module>` then `ddev drush en <module>` |
| Update core | `ddev composer update "drupal/core-*" --with-all-dependencies` then `ddev drush updb && ddev drush cex` |
| Database snapshot | `ddev snapshot` |
| Database export | `ddev export-db --file=backup.sql.gz` |

## Settings files

All live in `web/sites/default/`:

| File | Committed | Purpose |
| --- | --- | --- |
| `settings.php` | yes | Main settings. Sets `config_sync_directory` to `../config/sync`, reads the hash salt from `DRUPAL_HASH_SALT`, then includes the two files below. |
| `settings.ddev.php` | no | Generated by DDEV on start: database credentials and a development hash salt. |
| `example.settings.local.php` | yes | Template for local development settings. |
| `settings.local.php` | no | Copied from the template by DDEV on first `ddev start`. Edit freely. |
| `local.services.yml` | yes | Twig debug, auto-reload, and no Twig cache. Loaded by `settings.local.php`. |

`settings.local.php` turns on development mode:

- Twig debugging (template suggestions in HTML comments, `dump()`), auto-reload, no Twig cache
- Render, page, and dynamic page caches disabled
- CSS/JS aggregation off
- Verbose error messages
- Cacheability debug headers and lenient config schema checking (`development.services.yml`)
- Trusted host patterns for `*.ddev.site` and `localhost`
- Private files at `../private` (outside the web root)

If pages feel slow while working on back-end code, comment out the cache
lines in `settings.local.php`.

## Project layout

```
.ddev/            DDEV config and the custom `site-install` command
config/sync/      Exported Drupal configuration (source of truth)
recipes/          Drupal recipes
web/              Document root
  modules/custom/ Custom modules
  themes/custom/  Custom themes
composer.json     Dependencies
```

Composer-managed code (`vendor/`, `web/core/`, contrib modules and themes)
and scaffold files are not committed. `composer install` restores them.

## Hosting

The site is set up for local development only so far. When a host is chosen,
add its settings include to `settings.php` and set `DRUPAL_HASH_SALT` in the
host's environment.
